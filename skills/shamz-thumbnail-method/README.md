# The $shamz Thumbnail Method

A $shamz skill in the Shamz agent-skills collection. Build thumbnails the Shamz way: one fixed template per channel with a single variable slot, tight text gates, text baked in at generation, and a winner decided by watch time — never by taste alone.

## What it does

1. **Locks a fixed template per channel.** One typeface, one colour pair, one face-spot. Only one variable slot changes per episode, so every test teaches something attributable.
2. **Runs the one-second test.** Subject, action, emotion — readable at a glance, on a TV and on a phone, blurred and at 10–15% scale.
3. **Enforces the text gates.** One to four words, huge, completing the title and never repeating it, coloured from its own image, baked in at generation and never pasted on.
4. **Sketches five concepts and builds the top three.** Each variant tests a different hook axis under one locked title, including a textless pattern-break where the image is strong enough.
5. **Runs the packaging-first rule.** Thumbnail concepts lock at script stage; if no title pairs with any sketch, the idea is reworked, not the packaging.
6. **Checks the packaging triangle.** Thumbnail claim, title hook, and first spoken line must be the same promise — or the cold open is reordered to match.
7. **Zoom-inspects every variant at full size.** Identity, anatomy, continuity, readable text, crop, focal hierarchy, premise accuracy — fixed before presenting.
8. **Tests three variants and calls the winner by watch-time share.** At least 1,500 impressions per variant over about two weeks, never holding publication for the test.
9. **Logs the winner's DNA.** The winning expression, text length, composition, and palette become the next episode's default concept A.

## What you need

- The episode's premise, conflict, most surprising moment, and payoff
- The episode's locked character sheet (for any character-led thumbnail)
- The previous episode's approved thumbnails, as the style reference
- The channel's thumbnail system file (typeface, colour pair, face-spot) — or the decision to create one first
- A locked title, or three title variants for the later title round
- Access to the platform's thumbnail test tool for the test step

## How a run works

1. Read the story and find the single visual question — the image with the strongest curiosity gap.
2. Sketch five genuinely different concepts, lay them against the last three shipped thumbnails, and make one a deliberate pattern-break if the layout repeats.
3. Rank by clarity, build the top three under one locked title, and run the full QC checklist on each at full size and phone size.
4. Present the three labelled concepts with a recommended main; the creator picks the main.
5. Publish with the primary thumbnail and title — never hold publication for the test.
6. Start the three-variant test, wait the full run, and call the winner by watch-time share.
7. Log the result and lock the winner's DNA as the next episode's default concept A.

## Rules it follows

- One thumbnail = one idea. Bottom-right always clear. Subject 30–50% of the frame.
- Text is 1–4 words, completes the title, never repeats it, and is baked in at generation.
- The main thumbnail is a still from the episode; variants come from episode stills too.
- Character work matches the locked character sheet exactly, eyes checked on every thumbnail.
- No deception: every element in the thumbnail appears in the video. Real people and real events use real photographs, never AI lookalikes.
- Never change the thumbnail or title by hand while a test runs. Never change a thumbnail inside an active test window or distribution push.
- The number wins over taste inside the no-deception guardrail — once a test has resolved.
